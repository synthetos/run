# run.synthetos.com

The browser workspace for Synthetos CNC controllers: configure the board,
draw and check wiring, flash vetted firmware, and send G-code to run real
jobs, from desktop Chrome or Edge over Web Serial, tied to a Synthetos
account.

> **Status: Phase 0 (foundations).** Nothing in this repository can open a
> serial port or move a machine. Packages are filled in task by task; so far
> `protocol` has inbound framing and classification (P0-07) and the dialect
> data, read-only capability probe, capability classifier and signed
> approved-builds manifest (P0-08), and `schema` has the board definition
> schema and board selection (P0-08) and, from the vendored TinyG HIL tables,
> the per-dialect status tables and settings schemas, the read allowlists, the
> forbidden writes, the edge-next settings overlay, `validate` and the
> write-plan gate (P0-09); `safety` has the job sanitiser with long-move
> splitting, the allow-matrix, the overrun bound and the host-gate rule
> (P0-10).

> **This software is not an emergency stop.** Any machine it drives must have
> a hardwired, latching E-stop that removes motor and spindle power in
> hardware. Read the safety contract before connecting a machine: it is
> `SAFETY.md` in this repository, and is the `/safety/` page of the app.

| Path | Role |
|---|---|

| `packages/safety` | Allow-matrix, sanitiser, preflight, jog plan, flash gate, fault policy, overrun bound, warning strings |
| `packages/machine` | Transport interface, `MachineSession` (the single writer), flow engines, streamer, watchdog, stop sequences |
| `packages/schema` | Units, generated settings schemas, MachineProfile v2, fact engine |
| `packages/gcode` | G-code parser and dialect-aware interpreter and analyser |
| `packages/flasher` | Firmware manifest, HEX validation, xboot client |
| `packages/wiring` | Board data, components, rules engine, renderers |
| `packages/provenance` | Device-local trust anchor and authorship decisions (pure) |
| `packages/contracts` | API types and valibot schemas shared by the web app and the Worker |
| `packages/testkit` | **Dev only.** Firmware models and fakes for tests; never in a production bundle |
| `apps/web` | The workspace UI (Preact, Vite multi-page app) |
| `apps/cli` | Bench tooling (Node) |
| `workers/run` | The Cloudflare Worker serving the app, `/api/*` and `/auth/*`, and the single source of the security headers (`src/headers.ts`) |

| `tools/e2e` | **Dev only.** Playwright against `wrangler dev`, serving the local build (`pnpm e2e`) or the attested artifact (`pnpm e2e:artifact`, the CI `e2e` job): exact headers, CSP enforcement, Trusted Types, and the origin guard on every test, plus the third-party canary. `fake-serial/` is the test-only replacement for the machine worker's transport seam, and `*.fake-serial.ts` specs run against that build (`pnpm e2e:fake-serial`, P0-14) |

## Dependency rules

- `protocol`, `safety`, `machine`, `schema`, `flasher` and `provenance` have
  **no runtime npm dependencies** and never import network APIs, `contracts`
  or the cloud client.
- The cloud client (`apps/web/src/cloud`) imports only `contracts` and
  `provenance`, so never `machine`, `protocol` or `safety`, and the safety
  path never imports it.
- `workers/run` imports only `contracts`. The server holds no machine logic.
- No production entry may import `testkit`.
- Panels act only through typed intents checked by `safety.allowed`; no code
  outside `MachineSession` writes to the port, and nothing is loaded at
  runtime.

These rules are enforced by the gates below (P0-02, P0-03, P0-13).

| Gate | Command | What it enforces |
|---|---|---|
| Boundaries | `pnpm deps` | `.dependency-cruiser.cjs`: no npm (direct or transitive) and no Node built-ins in the safety path; no `contracts` or cloud client in the safety path; the cloud client imports only `contracts` and `provenance`; `workers/run` imports only `contracts`; no entry reaches `testkit`; nothing imports from outside the repository; every import resolves |
| Lint | `pnpm lint` | `eslint.config.js` with the repository's own rules in `tools/gates/src/eslint/`: no `eval`/`new Function`; no HTML sinks (`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `dangerouslySetInnerHTML`) outside `apps/web/src/security/tt.ts`; no `abort` in `machine`; no `Math.random` in `safety` and `protocol`; no network identifiers in `protocol`, `safety`, `machine`, `flasher` and `provenance`; no `navigator.serial`, `requestPort` or `getPorts` anywhere (until P1-01); no `WARNING —`, `DANGER —` or `NOTICE —` strings outside `packages/safety/src/strings.ts`. Inline `eslint-disable` comments are ignored (`noInlineConfig`), so a rule can be relaxed only in `eslint.config.js` |
| Licences | `pnpm licence` | Production dependencies: MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0 or OFL-1.1. Dev dependencies may also be MPL-2.0, or carry a reviewed exception in `tools/gates/src/licence/exceptions.ts`. GPL and AGPL are never allowed |
| CI policy | `pnpm ci-policy` | Workflows: only the deploy jobs touch secrets or the Cloudflare token; deploy jobs run only on a push to `main` behind protected environments; actions pinned by SHA; no `pull_request_target`; no `${{ }}` in scripts. CODEOWNERS covers every SAFETY §8 path. The PR template carries the SAFETY §8 checklist verbatim |
| Bundle scan | `pnpm scan` (after a build) | No origin literal, `//host`, `javascript:` URL or network identifier in `apps/web/dist` outside the cloud-client chunks (`assets/cloud/`, decided by content in `apps/web/build/chunks.ts`); the static-assets `_headers` file present and identical to what `workers/run/src/headers.ts` renders. Anywhere in the bundle (P0-13, T-S40): no test-kit marker, `MockSerialPort`, `transport=` query handling, URL scheme other than relative, `data:` and `blob:`, or Web Serial (`navigator.serial`, `requestPort`, `getPorts`); see docs/ops/ci.md |
| Reproducible build | `pnpm repro` | Clones `HEAD` twice, installs only the build toolchain, builds both and fails unless they are byte-identical, then scans |

`pnpm gates` runs lint, boundaries, licences and the CI policy. `tools/gates/test/acceptance.test.ts` proves
each gate fails on a violation: it copies the working tree, introduces one
violation, runs the real gate command and checks which rule caught it.

A change to `.dependency-cruiser.cjs`, `eslint.config.js`, `tools/gates/`,
`.github/` or `apps/web/build/` changes the safety boundary and needs
safety-path review (`.github/CODEOWNERS`).

## CI and deploys

`.github/workflows/ci.yml` runs these jobs:
- `verify`, secret-free;
- `build`, secret-free: the minimal build toolchain, two clean builds that
  must match byte for byte, and the bundle scan;
- `e2e`;
- `e2e-fake-serial`: the fake-serial test build, checked against the
  artifact, then its own Playwright suite (docs/testing/fake-serial.md);
- `attest`, which signs build provenance;
- `deploy-staging` and `deploy-production`, which run on `main` only, behind
  protected environments, and deploy only the attested artifact, then run
  the post-deploy smoke test.

The Worker, its headers, staging behind Cloudflare Access and the dedicated
Cloudflare account: docs/ops/worker.md, docs/ops/access.md,
docs/ops/account.md.

Pull requests that touch safety paths must carry the SAFETY §8 checklist and
two approvals (`safety-review`).

See `docs/ops/ci.md` for how it works, and `docs/ops/branch-protection.md`
for the GitHub settings the owner must enable. `SAFETY.md` is the in-repo
copy of the safety case.

## Development

Requirements: Node.js 22.18 or later (it runs the TypeScript gate and
bench scripts directly, with type stripping), and pnpm via Corepack (the exact
version is pinned in `package.json` `packageManager`).

```sh
corepack enable            # or prefix commands with `corepack`
pnpm install --frozen-lockfile --ignore-scripts
pnpm -r typecheck
pnpm gates                 # lint, dependency-cruiser, licences
pnpm -r test
pnpm --filter web build
```

`pnpm check` runs typecheck, the gates, tests, the build and the bundle scan
in that order, then the fake-serial test build and its diff against the
production build. `pnpm e2e` builds and runs the Playwright suite against
`wrangler dev` (`RUN_SCREENSHOTS=1` also writes the review screenshots to
`docs/design/screenshots/p0-05/`). `pnpm e2e:artifact` does what the CI
`e2e` job does: it assembles and verifies an artifact, runs the suite against
`wrangler dev` serving it, and runs the third-party canary (docs/ops/ci.md).
`pnpm e2e:fake-serial` builds the production and fake-serial builds, checks
that they differ only in the transport seam chunk, and runs the fake-serial
suite, in which `machine.worker` opens a mock port (docs/testing/fake-serial.md).

Pages and theme (P0-05): every page (`index.html`, `safety/`, `privacy/`,
`404.html`) is prerendered at build time from the Preact components in
`apps/web/src/shell/` and `apps/web/src/pages/`, so the safety bar and its W1
warning are in the HTML before any script runs. Every W and C string comes
from `packages/safety/src/strings.ts`, tested byte for byte against
`SAFETY.md` §5–§6 (T-S32). The bundle's version chip uses the commit SHA
(`git rev-parse HEAD`, or `RUN_BUILD_SHA`). Theme tokens, the token drift
check (`pnpm tokens:drift --site <synthetos.com clone>`), the contrast table
(`pnpm gen:contrast`) and the icons (`pnpm gen:icons`) are described in
`docs/design/tokens.md`.
Its nested `pnpm` calls need pnpm on `PATH` (`corepack enable`).

Protocol (P0-07): `packages/protocol` turns serial bytes into typed events.
`createInboundDecoder()` frames lines (CR/LF tolerant, UTF-8 safe, XON/XOFF
removed into `FlowSignal` events, 4 KB line cap) and classifies each one as
`Response`, `StatusReport`, `QueueReport`, `Exception`, `Banner`, `Ack`,
`Text` or `Garbled`, with a relaxed-JSON parser that has depth and size caps
and never throws. Anything ambiguous is `Garbled`, never guessed. Its tests
run with coverage, and `frame.ts`, `classify.ts`, `json.ts` and `inbound.ts`
must stay at 100% branch coverage (`packages/protocol/vitest.config.ts`).

Safety (P0-10): `packages/safety` decides what may be sent and when.
`sanitizeJob(lines, dialect, options)` applies SAFETY §4.7 step by step and
returns the exact `SentLine[]` the streamer will write (LF-terminated, host
`N` numbers, barrier and holdback marks, long moves split under the
queued-motion ceiling) plus a report; a blocked report must never be armed.
`allowed(snapshot, intent)` is the declarative allow-matrix (SAFETY §4.1):
the stop class is allowed in every state with the port open, and in Phase 0
every motion, write and connect intent is denied with "Not available in this
release". `overrunBound(queue)` gives the distance bound and the time
estimate of SAFETY §4.3, and `effectiveHostGates` applies only tightening
host-gate changes until C19 (T-S69). The package is held to 100% coverage
(`pnpm --filter @synthetos/safety test`) and a 90% Stryker mutation score
(`pnpm --filter @synthetos/safety mutation`). Design notes and the places
where the code had to interpret the design: `docs/safety/sanitiser.md`.

Dependency hygiene: versions are pinned exactly (`save-exact`), install
scripts never run (`ignore-scripts`), and pnpm refuses versions published
less than seven days ago (`minimumReleaseAge`).
